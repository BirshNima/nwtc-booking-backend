01 The principle

Rankings and clicks are not the goal — paying customers are. Every number here ladders up to one question: which sources, pages, and campaigns produce collected fares, and at what cost?

  • One tracker, everywhere. analytics/events.js loads on every page and the funnel. It captures attribution (first- and last-touch UTM + click ids) to localStorage and fires named events through the page's GA4 tag.
  • The funnel payload carries attribution. NWTCAnalytics.getAttribution() feeds source / medium / campaign / gclid into the Lead — so the CRM, not just GA4, knows where a booking came from.
  • Money events go back to Ads. offline-conversions.js turns "deposit paid" and "fare collected" into upload rows keyed on the click id. This is the step that makes paid search optimize correctly (and it is the gate on spending — see the growth plan).
  • No broad spend before this works. Confirm the chain end-to-end with a live test first.

02 GA4 setup

  1. Create a GA4 property + a Web data stream for northwesttowncarservice.com. Copy the Measurement ID (G-XXXXXXX).
  2. Add the standard gtag.js snippet to every page's <head>, then load analytics/events.js and call NWTCAnalytics.init({ measurementId: 'G-XXXXXXX' }).
  3. Mark these as key events: generate_lead, reservation_submitted, quote_requested, corporate_lead, call_click.
  4. Register custom dimensions (event-scoped) for: nwtc_source, nwtc_medium, nwtc_campaign, nwtc_click_id, service, service_area, quote_method, quote_value.
  5. Link Google Search Console to the property (organic query + landing-page data).
  6. Turn on Enhanced measurement but keep outbound-click and form tracking off — the explicit events below are cleaner.
  7. Later, when Ads exists: link Ads ↔ GA4, import the GA4 key events as conversions or use the offline import (§6) — not both for the same action.

06 Offline conversions

analytics/offline-conversions.js → buildConversionRows(records). Run it weekly against a CRM query of Bookings whose deposit or fare changed.

  • Two conversion actions in Google Ads, both count once: Deposit paid (value = deposit) and Fare collected (value = fare, mark this primary for bidding).
  • Rows are keyed on the click id the funnel captured (gclid / wbraid / gbraid, or msclkid for Microsoft) and stored on the Lead.
  • Clicks older than 90 days are skipped — Ads rejects them.
  • Upload via the Ads UI ("Conversions from clicks", toGoogleAdsCsv() matches the template) or the Ads API ConversionUploadService.
  • Set Smart Bidding to target Fare collected once ~15–30 conversions/month exist. Below that, stay on manual or maximize-clicks with tight budgets.
Why not just import the GA4 lead event

A generate_lead counts a wedding enquiry that never books the same as a paid airport run. Feeding Ads the actual deposit and fare — with their dollar values — lets it learn which clicks are worth more and bid accordingly.

07 Deploy & verify

  1. GA4 property + stream; snippet + events.js + init() on every page and the funnel.
  2. Add the track() calls: CTA buttons, tel: links, funnel step changes, quote_shown, and the three submit events (the funnel already imports the module — wire the calls in submitBooking() and goTo()).
  3. Custom dimensions registered; key events marked.
  4. Use GA4 DebugView + init({ debug:true }): click through the funnel, confirm every event and its params, including nwtc_source.
  5. Submit a real lead with ?gclid=TEST123&utm_source=google&utm_medium=cpc&utm_campaign=airport. Confirm the CRM Lead shows source=google, campaign=airport, gclid=TEST123.
  6. Mark that booking's deposit paid in the CRM; run buildConversionRows(); confirm one Deposit paid row with the right value and time format.
  7. Only when the whole chain is proven: turn on ad spend (growth plan, Phase E).
