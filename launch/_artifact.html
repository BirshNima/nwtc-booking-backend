Every step now has code or a plan on disk — booking-payment/, comms/, and analytics/ were the last three. What remains is running them: opening the accounts (Stripe, Twilio, an email sender, GA4, Airtable), deploying the handlers, and filling in the secrets. The phases below sequence exactly that.

PHASE A

Open the accounts

One sitting. Nothing here needs code — it is sign-ups and a few settings. Do them in this order so each has what the next one asks for.

~2 hrs · blocks everything downstream

A1Business email on the domain

Create book@northwesttowncarservice.com (Google Workspace, ~$7/mo). Every other tool sends "from" this address; the current gmail.com and yahoo.com addresses hurt deliverability and look ad-hoc on a quote.

Account: Google WorkspaceReferenced in: homepage footer, CRM intake

A2Airtable base from the CRM schema

Build the 11 tables exactly as the CRM blueprint lists them — field names and types matter because the intake transform writes to them by name. Follow the 9-step setup checklist at the bottom of that doc.

Account: Airtable (free tier is fine to start)Maps to: crm/index.html, crm/intake.js

A3Stripe account + one Payment Link

Verify the business, connect the bank account, make a single reusable "Ride deposit" Payment Link. No checkout is embedded in the funnel by design — dispatch sends the link only after confirming the ride is real. Keep card entry entirely inside Stripe's hosted page.

Account: StripeWires into: step 6 of the funnel, "Reserve" path

A4Twilio number + A2P 10DLC registration

Buy a local Seattle number and start the 10DLC brand/campaign registration the same day — carrier approval takes 1–3 weeks and it gates every automated text. Email can go live immediately through Workspace or a sender like Postmark; SMS waits on this.

Account: TwilioWires into: step 5 automations

A5Google Business Profile, Analytics, Search Console, Ads

  • GBP — claim/verify the listing; it is the single biggest local-SEO lever and it is free.
  • GA4 — create a property, grab the Measurement ID.
  • Search Console — verify the domain (DNS record), submit the sitemap once the site is deployed.
  • Google Ads — create the account now but do not launch campaigns until Phase E confirms conversion tracking fires.
Accounts: Google (GBP / GA4 / GSC / Ads)Plans: seo/index.html, growth/index.html
PHASE B

Stand up the data spine

The pricing table and the CRM are the two things everything else reads from. Get them authoritative before wiring anything to them.

~1–2 hrs · needs A2

B1Confirm every rate in the pricing table

Open pricing/index.html → Rate table tab. Walk all 14 airport zones and 6 hourly classes against what you actually charge today. This file is the one source of truth — the funnel and every rate board inherit from it. Tax and fuel surcharge are deliberately 0; leave them unless your accountant says otherwise.

File: pricing/pricing-table.jsonBump the version string on any change

B2Load real reviews into the CRM and the pages

Pull 3–5 genuine reviews from the Google Business Profile. Drop them into the <!-- Add real Google reviews here --> blocks on the homepage and airport page. Do not invent or pad — the pages ship with one real testimonial and that is fine until you have more.

Files: homepage-redesign/index.html, airport-transportation.html

B3Decide the open items below, then record them

Six decisions (next section) determine field values and vendor choices. Make them now so wiring in Phase C has concrete endpoints, not TBDs.

PHASE C

Wire the funnel to the spine

All the code for this phase is written — booking-payment/ (payments), comms/ (SMS + email), analytics/ (tracking), and the funnel already calls all three. What is left is deploying it and filling in the secrets, in an interactive session where you are logged in.

~3–4 hrs · needs A2–A5, B1

C1Deploy the three endpoints

booking-payment/server.js ships /intake (public: re-prices with verifyQuote(), writes the CRM via funnelPayloadToCRM(), alerts dispatch — no money), /deposit-link (dispatch-only, bearer token: creates the Stripe Checkout Session — the approval gate), and /stripe-webhook (marks the deposit paid). Adapters for Netlify / Cloudflare Workers / Express are in the file. Fill config.example.env → .env with test keys.

Uses: booking-payment/*, pricing-engine.js, crm/intake.jsBlueprint + test checklist: booking-payment/index.html

C2Set the funnel's endpoint + Airtable fields

Set window.NWTC_INTAKE_ENDPOINT on the funnel page to the deployed /intake URL (it already POSTs there, retries once, and shows a fallback message on failure). Add the Webhook Events table and the deposit fields on Bookings. Run the 8-step test checklist with Stripe test cards.

Files: homepage-redesign/booking-funnel/index.html, crm base

C3Wire the comms layer to CRM events

comms/ has every message (messages.js), the 4-touch follow-up state machine (sequences.js), delivery with dedupe + retry + STOP handling (send.js). Point each CRM automation at deliverAll(NWTCComms.plan(trigger, ctx)); run an hourly job over open quotes with NWTCSequence.nextAction(). Add the Messages table + the Lead/Customer fields it writes. Start with COMMS_DRY_RUN=1.

Uses: Twilio (10DLC), an email senderBlueprint: comms/index.html

C4Deploy the analytics tracker

Add the GA4 snippet + analytics/events.js + NWTCAnalytics.init() to every page and the funnel. The funnel already fires funnel_start, funnel_step, quote_shown, generate_lead and carries getAttribution() (source / campaign / gclid) into the payload — intake.js reads it onto the Lead. Register the custom dimensions, mark the key events, verify in DebugView with a test gclid.

Account: GA4Blueprint: analytics/index.html

PHASE E

Switch on demand

Only after a real quote has flowed end to end — funnel → CRM → dispatch alert → deposit link → GA4 event — do you spend on traffic. The growth plan is explicit: no broad spend before conversion tracking is proven.

Ongoing · needs C1–C4, D2 verified

E1Prove the tracking with a live test

Submit a real quote through the deployed funnel with a fake ?gclid=test123. Confirm: Lead appears in Airtable with source/gclid, dispatch gets the alert, GA4 shows the event. Fix anything that does not fire before spending a dollar.

E2Turn on the free channels first

Google Business Profile posts, the Local Services Ads application (pay-per-lead, screened), and the first 2–3 journal posts published on a cadence. These cost time, not budget, and they season the domain before paid traffic lands.

growth/index.html § LSA · seo/index.html content calendar

E3Launch paid on the lean tier

Start with the Airport and Corporate campaigns only, ~$1k/mo, exact-match and phrase, the negative-keyword lists applied from day one. Import offline conversions (booking confirmed, fare collected) back into Ads via GCLID weekly so it optimizes to revenue, not form-fills. Scale to the standard tier once cost-per-booking is known.

Full copy + structure: growth/index.html

OPEN

Six decisions only you can make

Each one sets a value or a vendor the wiring needs. Recommendations given; overrule freely.

1 · Deposit amount and refundability

Recommend: flat $50 deposit on instant-price rides, applied to the fare, refundable up to 24h before pickup. Custom quotes: deposit set per quote by you.

2 · Payment processor

Recommend: Stripe — best Payment Links, cleanest API for the offline-conversion loop later. Square only if you already run card-present terminals and want one dashboard.

3 · CRM / automation platform

Recommend: Airtable + Make for automations. The schema and intake code are written to it. Alternative: a real CRM (HubSpot free) if you want a sales pipeline UI out of the box — costs a re-map of the intake transform.

4 · Who gets the dispatch alert, and how

Recommend: SMS + email to one number/address for now (you). Add a second dispatcher later as a CRM field, not a code change.

5 · Follow-up cadence tone

Recommend: the day 0/1/3/7 schedule from the spec, but text only on day 0 and day 1; email for day 3 and 7. Opt-out honored automatically.

6 · Hosting: keep WordPress or move to static

Recommend: move to Cloudflare Pages. The new pages are static, faster, and free to host; WordPress adds attack surface and plugin upkeep you do not need. Keep WP only if you actively use its admin for something.

GUARDRAIL

What stays a human decision

Automate the reliable operations; gate the ones where a wrong automated move costs money or trust. This is the line from the system architecture — keep it after launch.

OperationHandlingWhy
Instant-price airport / hourly quoteautomaticRoute is reliably priced by the engine; verified server-side.
Confirmation, reminder, review requestautomaticDeterministic, time-based, low blast radius.
Lead capture & dedupeautomaticIdempotent on reference + normalized phone.
Custom / event / wedding quoteyou approvePricing needs judgment; engine returns "manual quote" by design.
Refunds & cancellationsyou approveMoney out; edge cases; goodwill calls.
Driver / vehicle change on a booked tripyou approveService-quality risk; customer expectations set.
Corporate contract & tier assignmentyou approveDiscount authority lives on the account, controlled by you.
Complaint responseyou approveRelationship recovery; never templated.
Unusual quote (long-haul, multi-day, out-of-area)you approveOutside the table's assumptions.
AFTER LIVE

First-week checks

  • Every funnel submission produced exactly one Lead — no duplicates, no drops.
  • Displayed price on the funnel equals the server-verified price on the Lead, every time.
  • Dispatch alert arrives within a minute of submission.
  • Deposit links resolve, and paid deposits mark the booking correctly.
  • GA4 shows the funnel events; Search Console is indexing the new pages.
  • No automation has fired twice for the same trigger.
  • Bounce/spam rate on the book@ sender is near zero.
The through-line: the whole point of this order is that traffic never arrives before the system that catches it. Homepage and ads are last, not first — when they turn on, a visitor lands in a funnel that prices the ride, files the lead, alerts dispatch, and takes a deposit. Not another contact form.
