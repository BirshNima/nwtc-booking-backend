Northwest Town Car Service

CRM schema & intake

Step 3 of the revenue core. Every enquiry — website, phone, or referral — lands as one record, deduplicated, tagged with where it came from, and moved through a status pipeline the owner can see at a glance. This is the exact base to build, and the contract that fills it.

v1 · 2026-09-02Target: Airtable (free) — HubSpot notes inlineFeeds from: booking-funnel

01 Overview

The funnel and pricing engine are done. Right now a website submission is logged to the browser and surfaced only through an email button. This step gives it a home.

Pick a platform

  • Airtable (recommended for now) — you control the schema exactly as below, the views are trivial to build, and its Automations cover most of Section 5. Free tier is enough to start. This doc is written for it.
  • HubSpot free — more polished CRM UI and email tooling, but you bend to its object model: Leads → Contacts, Bookings/Quotes → Deals with custom properties, Corporate Accounts → Companies. Fewer custom automations on the free tier. Notes inline where it differs.
  • The limo platform's built-in CRM (if you go with Moovs / Limo Anywhere) — one less tool, but weak on marketing segmentation and follow-up. You'd still want this schema's Leads and Corporate pipeline somewhere.

How it connects

booking-funnel → POST payload → intake.js (dedupe + status) → upserts → CRM → automations fire

The transform lives in crm/intake.js so the dedupe and status rules stay in one tested place no matter which platform or glue tool (Make, Zapier, a serverless function) applies the writes.

03 Relationships

Corporate Account ─┬─< Customers ─┬─< Leads ──1─ Quote
                   │              ├─< Bookings ─┬─1─ Trip ──> Driver, Vehicle
                   └────< Bookings              ├─< Payments
                                                └──── Reviews >── Customer, Trip

  ─<  one-to-many        ──1─  one-to-one        every write ──> Activity Log

A person is a Customer once; each enquiry they make is a Lead; a Lead that converts gets a Booking. Corporate trips link to both the Customer (the booker) and the Corporate Account (for billing and rate).

04 Views that run the day

The schema is inert without these. Build them as saved views on each table.

Leads

  • Inbox — Status = New, sorted by Created ↓. The first thing checked each morning.
  • Needs a quote — Quote Method = manual-quote AND Status in (New, Contacted). The dispatch work queue.
  • Follow-up due — Next Follow-up ≤ now AND Status in (Quote Sent, Follow-up).
  • Stale quotes — Status = Quote Sent AND Quote Expires < now.
  • This week — Created within 7 days (for the weekly count).
  • Lost — Status = Lost, grouped by Lost Reason (find patterns).

Bookings

  • Today / Tomorrow — Date = today / tomorrow, sorted by Time.
  • Unassigned — Status in (Reserved, Confirmed) AND Trip is empty. Escalate anything inside 12 h.
  • Unpaid — Deposit Paid = 0 AND Status ≠ Cancelled.
  • Completed this month — for revenue.

Corporate Accounts

  • Pipeline — Kanban grouped by Stage.
  • Stalled — Stage not in (Active, Inactive) AND Last Modified > 5 business days ago.

Customers

  • Lapsed — Last Trip > 120 days ago AND Segment ≠ Corporate. Feeds win-back.
  • VIPs — Trip Count ≥ 5, sorted by Lifetime Value ↓.

05 Automations

Build these in Airtable Automations, or in Make if you need branching Airtable can't do. Every one also appends an Activity Log row.

  1. Lead created → send the acknowledgement (email + SMS); if Quote Method is flat/hourly, the intake already set Status = Quote Sent and created the Quote — send that quote; if manual-quote, notify the owner it needs pricing; if corporate, the Corporate Account row already exists — notify the owner.
  2. Lead Status → Booked → create the Booking from the Lead's fields (if intake didn't already), set the Quote to Accepted, and stop the follow-up sequence.
  3. Quote Sent, no status change → the follow-up sequence at Created + 0 h / +1 d / +3 d / +7 d; advance Next Follow-up each step; at day 7 with no reply, Status = Lost, Lost Reason = "No reply".
  4. Booking Status → Completed → create a Review (Requested); send thank-you now, rating ask next morning.
  5. Review Rating set → ≥ 4: send the Google review link, Routed To = Google; ≤ 3: create an owner task, Routed To = Owner follow-up, do not ask for a public review.
  6. Nightly → recompute each Customer's Segment; flag Lapsed (no completed trip in 120 days).
  7. Corporate Account stalled → nudge the owner every 3–5 business days while Stage is between Contacted and Negotiation.
  8. Payment Status → Failed → retry once, then send the customer a card-update link; hold the Booking 24 h and alert the owner.
Approval gates carry over

From the system blueprint: unusual quotes, refunds, late cancellations, driver-change messaging, and any reply to a 1–3★ review wait for a one-tap human approval. In Airtable that's a checkbox field ("Approved to send") the automation waits on; in Make it's a router with a "wait for webhook" step.

06 Website → CRM intake

The funnel POSTs one payload per submission. crm/intake.js turns it into ordered upserts.

What the funnel sends

{
  reference: "NWTC-260902-4821",
  kind: "reservation" | "quote-request" | "corporate-lead",
  submittedAt: "2026-09-02T18:22:00Z",
  values: { service, zone, pickup, dropoff, date, time, passengers,
            vehicle, flight, stops, childSeats, notes,
            name, phone, email, company, volume, corpUse, consent },
  quote: { method, finalAmount, lineItems } | "corporate",
  source: "https://northwesttowncarservice.com/book?utm_source=google&utm_medium=cpc",
  gclid:  "Cj0K…"   // optional — Google Ads click id, if the site kept it
}

Rules the transform enforces

  • Dedupe the person. Match Customers on phone (digits, US-normalised), fall back to email. Update the existing Customer, don't insert a second.
  • Idempotent leads. Upsert Leads, Quotes, and Bookings on Reference — a double-submit or a webhook retry updates the same rows.
  • Status from kind + method:
    • reservation → Lead Booked, Quote Accepted, create Booking.
    • quote-request + flat/hourly → Lead Quote Sent, Quote Sent, Next Follow-up = +3 h.
    • quote-request + manual-quote → Lead New, Quote Draft (dispatch prices and sends it).
    • corporate-lead → upsert Corporate Account (Prospect) on Company, link the Customer, Lead New.
  • Attribution comes from the source URL — utm_* params, or gclid → google / cpc.
  • Never trust quote.finalAmount for a booking without re-running NWTCPricing.verifyQuote() server-side first (see the pricing README).

Applying the ops

funnelPayloadToCRM(payload) returns { ops: [...] }. Each op is { table, op: "upsert"|"create", matchOn, fields }. Apply in array order; _linkCustomer / _linkLead / _linkCorporate markers tell the applier to resolve a link from the record matched earlier. A ~30-line Make "Airtable: search then create/update" per table, or one Airtable script action, does the whole thing.

07 Stand it up

  1. Create an Airtable base "NWTC Operations". Add the 11 tables with the fields in Section 2 — start with Customers, Leads, Quotes, Bookings, Corporate Accounts, Activity Log; Trips / Drivers / Vehicles / Payments / Reviews can come with Phase 2.
  2. Set every Single select's options exactly as listed — the automations and the pricing engine match on these strings.
  3. Add the linked-record fields and the rollups/counts on Customers.
  4. Build the Section 4 views.
  5. Create an Airtable personal access token scoped to this base (data.records:read + write). Store it in your automation tool's secrets, never in the funnel.
  6. In Make (or Zapier): a scenario triggered by a webhook. Point the funnel's INTEGRATION fetch at that webhook URL.
  7. In the scenario: run intake.js's funnelPayloadToCRM in a code step, then a loop that applies each op with "Airtable → Search records" then "Create or Update".
  8. Test with the funnel: submit one airport booking, one wedding quote, one corporate lead. Confirm three Leads, three Customers (or fewer if you reused a phone), one Booking, the right Statuses, and three Activity Log rows.
  9. Turn on automations 1 and 3 (acknowledgement + follow-up). Add the rest as Phase 2 lands payment and reminders.
